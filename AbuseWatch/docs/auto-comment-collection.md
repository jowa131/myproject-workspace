# URL 기반 댓글 증거 수집 보조 흐름

## 목적

AbuseWatch는 사용자가 기사 URL을 제공한 뒤, 사용자가 실제로 연 브라우저 화면에서 보이는 공개 댓글을 한 번의 사용자 동작으로 구조화해 저장하는 도구입니다. NATE/네이버 댓글 페이지를 서버나 봇이 대신 돌아다니며 수집하지 않습니다.

## 사용 흐름

1. 로컬 앱을 실행합니다.

   ```powershell
   npm.cmd run dev
   ```

2. AbuseWatch에서 관심 키워드/대상을 등록합니다.
3. 사용자가 확인한 기사 또는 게시물 URL을 후보 URL 큐에 추가합니다.
4. 후보 URL 행의 `열기` 버튼을 눌러 사용자가 직접 새 탭에서 페이지를 엽니다.
5. 열린 페이지에서 보이는 댓글 영역을 한 번 선택한 뒤, 북마클릿 또는 확장 버튼의 `보이는 증거 저장`을 누릅니다.
6. 도구는 현재 열린 화면에서 보이는 선택 텍스트 또는 명시된 댓글 영역을 `captures` 배치 페이로드로 만들어 로컬 앱에 넘깁니다.
7. 로컬 앱은 배치 안의 댓글 후보를 각각 별도 증거 기록으로 저장하고, 사이트별 공개 핸들과 중복/유사 문구 묶음에 연결합니다.
8. 사용자가 증거를 검토해 승인한 뒤 신고 패키지를 생성합니다. 제출은 사람이 직접 합니다.

## 자동순회가 아니라는 뜻

자동순회를 하지 않는다는 말은 앱이나 확장이 다음 기사, 댓글 페이지 번호, 더보기 버튼, 무한 스크롤, 댓글 API, 관련 기사 목록을 스스로 따라가지 않는다는 뜻입니다. URL을 여는 행위와 캡처 시작은 사용자가 직접 수행합니다.

허용되는 자동화는 사용자가 이미 연 현재 화면 안에서, 사용자가 누른 순간에 보이는 댓글 텍스트를 여러 증거 기록으로 나누어 저장하는 것입니다.

## 안전 경계

- NATE/네이버 댓글 페이지 자동 순회 또는 무단 크롤링을 하지 않습니다.
- robots.txt로 차단된 경로를 수집하지 않습니다.
- 로그인 자동화, CAPTCHA 우회, 숨은 API 탐색, rate-limit 우회를 하지 않습니다.
- 실명, IP, 이메일, 전화번호, 위치, 기기정보, 인증 정보, 쿠키를 추적하지 않습니다.
- 동일 인물이라고 단정하지 않습니다. 사이트별 공개 핸들과 반복 문구 증거만 다룹니다.
- 신고를 자동 제출하지 않습니다. 신고 패키지는 사람이 검토하고 제출합니다.
- 공개 망신용 블랙리스트나 보복성 기능을 만들지 않습니다.

## 현재 구현

- 단일 `capture` 쿼리 import는 유지됩니다.
- 새 `captures` 쿼리 import는 1-50개의 표시 댓글 후보를 한 번에 받습니다.
- 배치 안의 댓글 하나라도 안전하지 않으면 전체 배치를 거부합니다.
- 북마클릿과 확장 스크립트는 현재 탭의 표시 내용만 읽고 원격 요청을 만들지 않습니다.
- 후보 URL의 `열기`는 일반 링크이며, 원격 페이지를 앱이 미리 요청하거나 검증하지 않습니다.
