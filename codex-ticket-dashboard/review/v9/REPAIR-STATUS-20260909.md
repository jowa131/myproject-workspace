## 이번 진행에서 발생한 총괄 오류

1. 소스 명세의 runtime_root를 src 대신 제품 설치 루트로 잡아 설치 영수증 103개가 미등록 파일로 차단됐습니다. 소스·의존성은 재복사하지 않고 새 명세 2개만 설치해 교정했습니다.
2. 기동 보조 스크립트의 ACL 인자 조합과 기존 명시 ACL 보존 문제가 실행 전 두 번 발생했습니다. 기존 설치기의 원자적 사용자 전용 파일 생성 방식을 재사용해 교정했습니다. 이때 제품 프로세스는 시작되지 않았습니다.
3. 서버 PID와 부모 PID를 혼동한 확인 명령이 정상 시작한 수집기를 종료시켰습니다. runtime.py의 os.getpid()/os.getppid() 계약을 확인하고 검사만 교정했습니다.
4. 큰 승인 명세를 요약 없이 출력해 불필요한 출력을 만들었습니다. 명세 조회는 선택 필드·개수·불일치만 출력해야 합니다.
5. 앱의 작업 조회가 실제 진행보다 늦은 상태를 반환했습니다. 원본 완료 이벤트와 생성 파일로 상태를 정정했습니다.

이 오류들을 제품 결함·유닛 테스트 실패와 구분하며, 사용자 지시 부족으로 돌리지 않습니다. 설치 전에는 소스 명세 루트와 실제 import 루트의 동일성, 설치 영수증의 범위, 기동 프로세스의 부모·자식 계약을 확인해야 합니다. 권한 생성은 기존 검증된 설치 함수를 그대로 재사용해야 합니다.

## 릴리즈를 위해 남은 작업

1. 제출 Hook의 실제 발화 여부, 실행한 명령, 프로세스 시작·종료 코드와 제한 시간 초과 여부를 원문 없는 영수증으로 구분합니다. 현재 실패 원인이 확정되기 전에는 같은 일반 요청이나 시간 측정을 반복하지 않습니다.
2. 확인된 해당 경계만 수정하고 영향받는 핵심 유닛 테스트를 실행합니다. 일반 작업의 UPS→MCP→spool→티켓 반영이 연결돼야 합니다.
3. 기본 경로 성공 뒤에만 새 작업·재개·하위 작업과 상태 전이의 미검증 조건을 최소 대표 사례로 확인합니다. 기존에 통과한 저장·보안 검사는 변경 영향이 있을 때만 다시 실행합니다.
4. 확인용 설정 복구·시험 서비스 종료 후 기존 논리 프로젝트의 운영 등록과 주 프로젝트 연결을 적용합니다. 현재 설치는 확인용 환경이며 운영 전환이 아닙니다.
5. 설치·복구 안내와 실제 사용 결과를 고정하고 사용자 수락을 받습니다. 모바일·Chrome 200% 확대의 기존 보류를 통과로 바꾸지 않습니다.

이번 실제 작업 실패 뒤 추가 모델 요청·전체 시험·추정 소스 수정은 하지 않았습니다. 자동 업무 등록이 없는 현재 상태를 완성품으로 선언하지 않습니다.
